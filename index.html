OCR engine benchmark · 21 Oct 2026

Tesseract 5 vs Indra OCR on a 248-page PDF

Both engines were run through the Integra Studio web app in Chrome, with forced OCR on every page of a 248-page born-digital test PDF. A second, per-page harness timed the OCR call alone and scored accuracy against the PDF's own embedded text layer, which serves as exact ground truth.

4 · Error analysis

What each engine gets wrong

Most frequent character edits

Reference → OCR, summed over all pages. ∅ means the character was dropped. Space→newline edits are line-grouping noise common to both and are excluded.
  • Tesseract drops characters. Its top errors are deletions of I, 1, A, 2, 0 and N, mostly in narrow, tightly packed text. That is why 11% of its dates are wrong.
  • Indra substitutes. It confuses l/I (396) and reads some 2s as $ (138) and 6s as @ (21). That is a risk for numeric data, though only 12 of 8,612 decimal numbers were wrong.
  • Both are strong on decimal numbers. Tesseract got 99.72% exact and Indra 99.86%, which means 24 versus 12 wrong values across the whole document.

6 · Method

How this was measured

  • Chrome runs. The app UI was driven through Claude in Chrome: upload the PDF, pick the engine, tick “OCR every page”, convert. Tesseract ran first, then Indra. A hook on the page's XHR recorded upload time, total time and the server's X-Extract-Ms / X-Excel-Ms headers.
  • Fresh server. The running :8000 server had not reloaded the current code, so it ignored forced OCR and read the text layer instead (141.8 s, kept here as the reference). The benchmark used a fresh instance of the same code on :8001. Indra's Chrome run therefore includes its 5.0 s cold model load.
  • Per-page harness. Each page went through the app's own render and line-mask steps, then only words_from_ocr or words_from_indra was timed. Each engine ran in its own process, one after the other, with nothing else running.
  • Ground truth. The PDF is born-digital, so its embedded text is exact. CER and WER are Levenshtein distances over reading-order text. Line grouping adds identical noise to both engines, so read absolute CER as an upper bound and the gap between engines as the result.
  • Limits. One document with one layout, one run per engine, one 4-core laptop, one request at a time. Tesseract's single-threaded profile means parallel workers would likely raise its throughput much more than Indra's. That is an inference from the CPU data and was not measured.
